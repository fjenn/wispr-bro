# RS-05: clipboard and paste test, how to run it

When Wispr Bro pastes your words, it puts them on the clipboard for a moment,
presses ⌘V for you, and then puts back whatever you had copied before. This
test checks that this works in your apps, and that what you had copied
(text, styled text, a web page, files, a picture) comes back exactly. It
takes **about 10 minutes**. Nothing leaves your Mac.

Your own clipboard is saved before the test starts and put back at the end,
even if you stop early.

## Start it (3 steps)

1. Open **Terminal** (press ⌘ Space, type `Terminal`, press Enter).
2. Copy this line into Terminal and press Enter:

   ```sh
   ~/Projects/wispr-bro/scripts/wb-spike-clipboard.sh
   ```

   The first time, it spends about a minute getting ready.

3. Follow what it says on screen. Make the Terminal window narrow and keep
   it at one side, so you can read it while other apps are in front.

To stop at any time, press **Control + C**. Your clipboard is put back and
what was done up to then is kept.

## What will happen

- **Permission.** The test presses keys for you, so Terminal needs
  Accessibility (System Settings → Privacy & Security → Accessibility →
  Terminal: on). It is probably on already from the fn test. If not, the test
  opens that page and waits. If macOS says Terminal must quit and reopen, do
  that and run the same command again.
- **Step 1 (30 seconds, hands off).** Press Enter. The test opens a TextEdit
  document, a Safari page and a Finder window by itself and copies from them.
  Don't touch the keyboard or mouse until the Terminal window comes back.
- **Step 2 (about 5 minutes): your apps.** For each app (TextEdit, Notes,
  Mail, Messages, Terminal, Safari, Chrome, Cursor, Obsidian, Claude,
  ChatGPT):
  1. press Enter: the app comes to the front, with a new empty document where
     it can;
  2. click where you would type (the screen says where; for TextEdit, Safari,
     Chrome and the extra Terminal window the test usually starts by itself);
  3. take your hands off the keyboard and mouse. The test pastes six times,
     "[dictated text 1]", "[dictated text 2]" and so on, each time with
     something different on the clipboard;
  4. a sound plays and this window comes back. For apps the test cannot read
     by itself, it asks how many arrived and whether anything else appeared.

  Nothing is ever sent: in Messages, Claude and ChatGPT just never press
  Return. To skip an app, type `s` and press Enter.

- **Step 3 (1 minute): holding Control and Command.** A TextEdit window
  opens. Press and **hold** Control (⌃) and Command (⌘) together until you
  hear a sound, then let go. Then hold them again and let go **as soon as**
  you hear the sound. Don't press any other key. One yes/no question follows.
- **Step 4 (optional, 30 seconds): a Japanese keyboard.** The test asks
  first. If you say yes, it turns on the Japanese input method for a few
  seconds, pastes twice into TextEdit (once while a word is half typed; it
  types "nihon" itself), and then turns it off again and checks that your
  list of keyboards is as before. Answer `n` to skip.
- **At the end** it prints a short result and a list of windows to tidy up
  (test documents, test tabs, a draft in Mail, the test text in Notes,
  Messages, Obsidian, Claude and ChatGPT). Results go to
  `~/wb-bench/results/rs05/<date-time>/`. Tell Claude you're done.

What is saved: which types were on the clipboard and their sizes, timings,
whether each paste arrived, and your answers. The contents of your own
clipboard are never written to the log; a copy is kept in the results
folder only until it has been put back, then deleted. All of it stays on this
Mac.

If the test ever stops before putting your clipboard back (for example the
Mac restarts), run the same command again: it notices and offers to put it
back. Or run
`~/Projects/wispr-bro/scripts/wb-spike-clipboard.sh --restore-owner <results folder>/owner-clipboard.wbclip`.

## For the team: what this run covers and what it doesn't

The tool is `src-tauri/crates/wb-spike-clipboard` (its own workspace and
lockfile, a pruned copy of the app's). `src/clip/` is the prototype of
`fork/clipboard/` that S-04 lifts (see `src/clip/mod.rs`); `src/take.rs` is
one paste the way `fork::insert::deliver` will do it:

1. wait for ⇧⌃⌥⌘ and fn to be physically up (hex's poll of
   `CGEventSourceFlagsState`, max 3 s, 5 s in the held test);
2. snapshot every `NSPasteboardItem` and type via objc2, leaving out file
   contents/promises, PDF, RTFD and audio (`snapshot.rs` `skip_reason`);
3. write one item: `org.nspasteboard.TransientType`, `AutoGeneratedType`
   (hex) and `ConcealedType` (Handy's concealed paste,
   `paste_tx/macos.rs` `CONCEALMENT_TYPES`) as eager empty data, and the text
   as a lazy promise (`setDataProvider:forTypes:`), whose callback is the read
   receipt;
4. ⌘V via CGEvent at the HID tap with explicit ⌘ flags, key code from the
   layout (Handy `input.rs` resolver); for Chromium 155/156 the product path
   types instead (hex, ≤ 20 UTF-16 units per event);
5. wait: a read after the ⌘V, then 200 ms quiet; or 1.5 s (native) / 7 s
   (Chromium, Electron) without a read; or the `changeCount` moved;
6. restore only if hex's guard agrees (same generation and `changeCount`
   unchanged; back-to-back takes carry the real snapshot forward), then read
   back and compare byte for byte.

Modes: `--dry-run` (apps, versions, permissions; touches nothing),
`--auto` (round trips and guard checks only: no key presses, no windows),
`--self-check` (`--auto` plus real copies from TextEdit/Safari/Finder and
the paste matrix in the four apps that need no click: TextEdit, a new
Terminal window running `cat` into a file, and a local test page in Safari
and Chrome; the IME step only if a CJK source is already on, or with
`WB_RS05_SELFCHECK_IME=1`). Output per run: `summary.txt`, `summary.json`,
`events.jsonl`, plus the generated `sources/` and `targets/` files.

How "landed" is decided without asking: TextEdit, Notes, Mail, Messages and
ChatGPT through Accessibility (`AXFocusedUIElement` → `AXValue`); the test
page mirrors its text box into the window title (read as `AXTitle`); the
Terminal window's `cat` writes what it receives to a file. Cursor, Obsidian
and Claude (Electron, no AX tree without `AXManualAccessibility`, which is
RS-04's business) and any app whose field cannot be read fall back to the
owner's answer.

Compared with the RS-05 row in R5 §7:

- **Clipboard managers:** Maccy, Raycast and Paste are not installed and the
  owner asked not to install anything, so the manager criterion stays
  **untested**. The tool reads back what a manager would see during the paste
  window (types only, which does not fire the lazy text) and checks that the
  transcript item carries all three markers and nothing else is on the
  clipboard.
- **Apps:** the §5.4 list has Slack, VS Code, Notion and Chrome Gmail, which
  are not here. Cursor, Obsidian and the Claude/ChatGPT apps stand in, and
  Chrome gets a local test page (no network). ChatGPT's bundle on this Mac is
  `com.openai.codex` with a Chromium 156 framework.
- **Sources:** RTF, HTML, file and two-file copies are real copies from
  TextEdit, Safari and Finder; plain text and the PNG are written by the
  tool (the owner's screenshot clipboard is not used). PDF, RTFD and audio
  are only exercised by the skip-policy guard check and unit tests.
- **CJK IME:** Japanese (Romaji) only; Pinyin is not tried. The "half-typed
  word" variant uses keys the tool posts, not the owner's typing.
- **Not covered:** the restore write being recorded by a manager as a new
  copy (RT-24's second half), paste verification as the product will do it
  (`AXValue` change ≤ 300 ms → `confirmed`/`unverified`; the tool's own check
  is a prototype of it), the card's Copy and ⌃⌘V/⌃⌘C bindings themselves
  (S-06), and sleep/lid/user switch during a take (S-04).
