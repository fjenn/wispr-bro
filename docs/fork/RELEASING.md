## GPL release assets (F-04): TODO for F-02

`wb-release.yml` does not exist yet. When F-02 creates it, the job that
publishes the GitHub release must also upload these two assets to every
release (stable, beta and drafts alike), from the same commit as the build:

1. **`THIRD-PARTY-NOTICES.md`**
   - Run `bun scripts/wb-notices.ts --check` on the tagged commit (it needs
     `cargo-about` 0.9.3: `cargo install cargo-about --locked --version 0.9.3 --features cli`,
     already installed by `wb-ci.yml`'s `licences` job). It fails if the
     committed file is stale or any licence is not accepted, so the release
     fails rather than shipping wrong notices.
   - Upload the committed file as a release asset, next to `LICENSE` and
     `NOTICE` (also upload both).
2. **Source tarball** `wispr-bro-<version>-source.tar.gz`
   - `git archive --format=tar.gz --prefix=wispr-bro-<version>/ -o wispr-bro-<version>-source.tar.gz <tag>`
     on the tag being released. It contains the complete corresponding
     source: our code, Handy's code, `about.toml`, the build scripts and
     workflows (incl. the S-10 `llama-server` CI build once it exists) and
     the overlay config `src-tauri/tauri.fork.conf.json`.
   - GitHub's automatic "Source code" archives are not enough on their own:
     they are not part of the release assets we control and cannot be
     checksummed in the release notes.
   - If a release ever ships a prebuilt binary that contains GPL code and is
     not built from this repo by the workflow (e.g. a rebuilt `.a`), its
     sources and build script go into the repo first.

Checklist for the F-02 PR:

- [ ] `wb-release.yml` runs `bun scripts/wb-notices.ts --check` before
      publishing.
- [ ] The release has `THIRD-PARTY-NOTICES.md`, `LICENSE`, `NOTICE` and
      `wispr-bro-<version>-source.tar.gz` as assets.
- [ ] The release notes link the source tarball (GPL-3.0 §6).
- [ ] Homebrew and any mirror point at the same GitHub release.

## Why THIRD-PARTY-NOTICES.md is committed

It is generated by `scripts/wb-notices.ts` but committed, so every
dependency change shows its licence diff in review. `wb-ci.yml`'s
`licences` job runs `--check` on every PR (macOS runner, same target set
as the release build), so the committed file never drifts. Regenerate with
`bun scripts/wb-notices.ts` after any change to `Cargo.lock`, `bun.lock`,
`NOTICE` or the catalog's CC-BY models.
