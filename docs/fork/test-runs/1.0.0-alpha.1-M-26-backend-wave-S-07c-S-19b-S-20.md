### Notification Open — product blocker

A second real offline/online producer generated `1 dictation ready`. This command reached the app:

```sh

```

The log proves the action was received: `entry 3 (queued_takes_ready) activated via System button open → OpenPage { page: "settings", section: Some("history") }`. **The visible window nevertheless remained on onboarding**, not History (`s07c/open-action-history.png`). The prescribed S-20 profile/setup and real SIGUSR2/speaker path ran TextEdit, the Chrome Slack-thread stand-in, Card number and Terminal cases:


- **Unusual surname PASS:** context-on TextEdit rows 1 and 4 changed ASR `Kovalczyk` to final `Kowalczyk`, with `context_used=1`; context-off row 3 remained `Kovalczyk`, with `context_used=0`. Siobhán and Thibault were not corrected in these real takes; this is not counted as a pass for them.
- **Latency PASS:** six real `context: read` lines, including off/excluded reads, had p95 and max **53.5 ms**. The eval's added p95 is separately reported above.
- **Clipboard PASS:** every S-20 take's full clipboard digest was unchanged.
- **Nearby-text persistence PASS:** after stopping the app, recursive Data/log searches and every text value in every DB table had zero hits for `Zebulonix`, `Quarterbridge`, the context sentence and the other unique nearby sentences. DB rows store only the `context_used` bit, not the nearby text.
- **Terminal exclusion PASS:** `context: read terminal (0 char(s), 0 hint(s), 0.3 ms)`.
- **Card number exclusion FAIL:** the Card number take logged `context: read ok (180 char(s), 3 hint(s), 7.5 ms)`. Both context and insertion logs show Chrome had no focused element (`role:null`, `no_element_with_window`). In `src-tauri/src/fork/context/caret.rs:763-793`, sensitive-label/numeric/secure checks run only when `AXFocusedUIElement` exists. With it missing, the code proceeds to the generic window walk and reads nearby text instead of failing closed. This is a product privacy defect, not a markup problem: the shipped test field has both `aria-label="Card number"` and `placeholder="Card number"`. No fix was made.

Two context-on TextEdit deliveries and the Chrome takes became cards because `modifier_wait_timed_out` reported held modifier keys; the context-off TextEdit take pasted successfully. This affected insertion, not the ASR/final-text, context-bit, clipboard or privacy evidence above. Slack itself, a real colleague and VoiceOver remain person checks and were not run.

## Follow-up fixes and reruns

Source after the follow-up merges: `62e700f6` on `wispr-bro`.

- **S-07c notification Open: PASS.** The fix in `c71ff55b` lets a native Open action mount the Hub without completing or changing onboarding state. The run left onboarding incomplete, as required. WebKit did not expose the Hub's expected AX nodes in this run, so the window screenshot is the acceptance evidence.
- **S-20 first sensitive-field follow-up: still failed.** Its Card number rerun logged `context: read ok (220 char(s), 3 hint(s), 21.3 ms)`. A leased AX diagnostic proved that Chrome exposes `AXTextField` with title/description `Card number` and accepts the exact 14-attribute batched request. The actual defect was narrower than the first fix: generic focus such as `AXWebArea` caused `lines_around` to skip that focus element's whole subtree, so the Card input was never inspected while surrounding text was read.
- **S-20 generic-focus follow-ups: PASS.** `d741aedd` narrowed the focused walk, but subsequent Card reruns still read 205 chars. Temporary counts-only tracing (removed after diagnosis) showed that default Chrome had no focused element and exposed only 36 browser-window/toolbar elements, with no `AXWebArea`; the five-char difference from the ordinary control was the address bar's `#card` suffix. Final fixes `e85c2380`, `7bd1e520` and `e7f3fd78` gate generic caret pre-reads, inspect skipped/offscreen/failed-batch subtrees, reject aggregate `AXWebArea` values, and return `no_access` rather than harvesting browser chrome when no page is inspectable. The isolated S-20 Chrome profile now uses `--force-renderer-accessibility`; the ordinary fixture no longer contains a Card input, while `#card` creates and focuses it. Final evidence: `rerun/s20-generic-focus/131118-card/log` is `context: read sensitive (0 char(s), 0 hint(s), 1.4 ms)` with no `read ok`; `131134-chrome/log` is `context: read ok (448 char(s), 8 hint(s), 25.1 ms)`. Both full clipboard digests stayed unchanged. Slack itself, a real colleague and VoiceOver remain unrun person checks.
- **Download-resume regression:** `c03150f4` makes the test mirror concurrent and blocking, holds resumed ranges until the first relaunch progress update is asserted against the exact committed offset, then checks the checksum. The targeted test passed 100 consecutive runs; no product code changed.
- **Final non-GUI regression net:** full Rust suite **1,330 passed, 30 ignored**; Playwright **272 passed, 10 skipped**; `wb:guards`, ESLint and the post-documentation `wb:format:check` passed. The parallel format gate's only failure was Playwright's generated `test-results/.last-run.json`, which was removed as test debris before the successful rerun.
