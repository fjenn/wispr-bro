OT2-D on ⌃⌥1/⌃⌥2 (`WB_OT2D_MOD=ctrl-opt`). OT2-C in a throwaway Cursor (`--user-data-dir` under `/tmp/wb7c`).
- **Screens:** the test app's own window, `screencapture -l`, light/dark, English/Arabic/Turkish/Italian/German, routes through `WISPRBRO_HUB_ROUTE`; menus opened by clicks on our own window (only while it was frontmost).
- **Owner at the Mac:** before each step that posted input or changed focus, HID idle ≥ 120 s and the screen unlocked. Our own synthetic events reset the idle counter, so the session scripts now wait up to 5 min for 120 s of quiet before each step (they stopped twice when the owner came back).
- **Profiles:** shortcuts unbound (`wb_unbind_keys`), models cloned from `com.wisprbro.s20check` (read only), `HF_ENDPOINT=http://127.0.0.1:9`, `WISPRBRO_DISABLE_UPDATER=1`. Clipboard saved and restored around every take; checked byte-identical.
- **Evidence:** session scratch dir `macwave-7/` (`shots/`, `ot2a/`, `s05/`, `ot2d/`, `s36-on*/`, `logs/`, `results.tsv`), never committed; screens page `macwave-7/index.html`.

## Incidents

1. **A test app downloaded a speech model (fixed, `8068d0cc`).** The first OT2-A session started the S-05 debug build from `src-tauri/target/debug`, which had no `portable` marker (removed by an earlier cleanup). The app therefore used `~/Library/Application Support/com.wisprbro.w7check` instead of `Data/`, ignored the cloned models and downloaded parakeet-tdt-0.6b-v3 Q8_0 (739 MB) from Hugging Face (09:29 UTC). That folder belongs to a test identity, not the owner's; it was deleted at the end of the run. `scripts/wb-s05/app.sh start` now writes the marker, refuses to start without it, and points `HF_ENDPOINT` at a dead loopback.
2. **A synthetic ⌘ stayed "held" in the HID event state (fixed, `dd690623`).** `scripts/wb-s25/ui.swift` posted `cmd-s`/`cmd-z` as a key down and up that both carried ⌘, with no modifier release. Afterwards `CGEventSource.flagsState(.hidSystemState)` reported ⌘ held, and the next three Cursor takes waited 3 s for "modifier keys were still held" and went to the card: nothing was pasted anywhere and the text stayed on the card. It was cleared with one key-up event; `ui.swift` now ends every chord with a modifier release, and the re-run pasted normally. The combined session state stayed 0, so the owner's typing was most likely unaffected; the owner was idle during that window.
3. **card:password opened a page in the owner's running Safari** (first S-05 session). The driver's `open_safari` made a new document in Safari, brought Safari to the front, then closed that document. No other Safari window or tab was touched and nothing was typed. The case now uses the driver's own Chrome instance (`5cb47833`).
4. **OT2-D's full-screen evidence shots** (`screencapture -x`) captured the owner's screen. They were cropped to the bar at the bottom centre and the full frames deleted; nothing left the scratch dir.
