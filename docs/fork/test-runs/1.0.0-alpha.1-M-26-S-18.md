## What we learned

- **Ad-hoc builds can use `UNUserNotificationCenter`**, but only from a
  location LaunchServices accepts: from the scratch dir under `/private/tmp`
  usernoted logged `Failed to find or validate client of identifier …` and
  every request failed with "Notifications are not allowed for this
  application"; the same bundle in `~/Applications` (registered) prompted and
  delivered. A process started by running the bundle executable directly is
  accepted once the bundle sits there.
- **A debug build cannot be launched with `open`**: Handy's `lib.rs` exports
  TypeScript bindings relative to the working directory in debug builds and
  panics on the read-only `/` that LaunchServices gives it. The S-18 procedure
  uses a release build (the demo also runs with `--debug`).
- **With a Focus on, banners are held**: usernoted resolves "delay
  delivery"; the notifications wait in Notification Center, where their
  clicks and buttons behave exactly as on a banner.
- **`--start-hidden` reports a focused window**; S-18 now counts a window as
  in front only when it is visible, not minimized and focused.

## Clean-up

Both test identities' notifications were closed in Notification Center, the
bundle was unregistered (`lsregister -u`) and deleted, and its
`~/Library/WebKit` and `~/Library/Caches` folders removed. `tccutil reset`
could not run after the unregistration (it needs the bundle); the run asked
for no TCC permission. macOS keeps a "Wispr Bro S18 Check" row under System
Settings › Notifications until it prunes apps that no longer exist; there is
no supported command to remove it (`com.apple.ncprefs` lists no row for the
identifiers).
