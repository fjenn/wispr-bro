text pipeline → cleanup on the sidecar → stage 10 → paste) with

through the speakers into the built-in mic at volume 50. TextEdit stands in
for the apps of each group: `scripts/wb-s19a/setup.py` writes an
`app_rules` row putting TextEdit in the group under test, so the chain from
the frontmost app through the user's rule, the preset and the cleanup to
the field is the real one. Slack is not installed on this Mac; Messages and
Mail hold the owner's real conversations and drafts and were never typed
into. The general pasteboard was empty before and after the run
(`scripts/wb-s17/clip.swift`).

Partway through, the system output was muted by something other than this
run (no mute call in the app's log; `mute_while_recording` off), and takes
from then on recorded silence (`cleanup: skipped … empty`). For the
auto-send phases the output was unmuted, the phases run (about 20 s of
speech), and the mute put back at once (`output muted: true` as found).

- No style: identical to S-12a's gate run (en filler 95.6 %, nl 94.4 %,
  fr 95.5 %). All RS-07 Light and Medium gates pass.
- Presets: no preset changes the prompt, so each preset's run is the
  no-style run with stage 10 applied to the English rows
  (`fork::llm::eval_run::eval_restyle`, `scripts/wb-s19a/restyle.sh`):
  378 English rows; changed by Relaxed 217, Very relaxed 349, Upbeat 211,
  Formal 0. Every gate is unchanged. An earlier Relaxed run lost a comma
  inside code (`code-009`, `items.reduce((a, b) => …)`, damage 0.4 %);
  commas inside brackets and backtick code now stay, and the item passes.
- An Upbeat prompt fragment of our own (two wordings, `WB_EVAL_STYLE=upbeat`)
  caused guard fallbacks on multi-line and self-repair items (`mixed-004`,
  `mixed-006`); the Light "language kept" gate fell to 98.3 % (58/59), below
  99 %. It is not shipped. A second full replay made while other agents
  loaded the machine (p50 ~900 ms, request timeouts) was discarded as not
  comparable.
