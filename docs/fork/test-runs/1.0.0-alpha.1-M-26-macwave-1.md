## Findings

1. **S-24: the Scratchpad window showed the Hub (fixed).** `fork/scratchpad/window.rs` loaded `fork-scratchpad.html`, but Vite emits the input at its source path (`dist/src/fork/scratchpad/index.html`, like the Flow Bar's `src/fork/pill/index.html`); the unknown path fell back to `index.html`, the Hub. Fix: `fix/macwave-s24` (`PAGE` constant, the test now checks that exact file exists). Verified in the real app: ⌥S opens the note editor and S-24.3 passes.
2. **Dictating while Wispr Bro's own window is in front crashed an unbundled build (fixed), and still loses focus.** The S-20 read at record start ran `AXUIElementCopyMultipleAttributeValues` on Wispr Bro's own process from the `wb-ax` thread; AppKit answered in-process and WebKit aborted (`EXC_BREAKPOINT`, `crashDueToApplicationCallingMainThreadOnlyWebKitAPIFromBackgroundThread`, crash report kept locally). The own-app exclusion matched only a `com.wisprbro.` bundle id, which `tauri dev`/`--no-bundle` builds lack. Fix: `fix/macwave-s20` (`19557b6e`, skip when the frontmost pid is this process, with a test); rerun logs `context: read own_app` and the app stays up. Separately, on both the fixed `--no-bundle` build and a bundled `s24check` build, the app stops being frontmost within 0.2 s of a take starting from the note (the previous app gets focus back), so S-24.1 still fails; needs the S-24 owner (the per-take Flow Bar web view is the first suspect).
3. **S-24: ⌥S does not give the note keyboard focus.** The window opens floating and inactive; typing still goes to the previous app. `open()` calls `set_focus()`, which macOS 26 ignores for a background accessory app.
4. **S-27.5: `.ips` copies are sanitized by pattern only.** A body line `{"note":"zebra lantern quartz crash body"}` was copied verbatim; `Transcript: …` lines and the home path are redacted. A crash report that quotes user text (a panic message) would reach Save/Copy diagnostics. The S-27 checklist's "any body line containing the marker" therefore fails; decide whether the pickup should keep only the header and stack frames.
5. **S-29a.5 cannot pass on a debug build.** After the move the app relaunches through LaunchServices with cwd `/`; Handy's `#[cfg(debug_assertions)]` specta export to `../src/bindings.ts` (`lib.rs:800-806`) panics on the read-only root. Release builds skip that export. Either run S-29a.5 on a release build or make the debug export best-effort.
6. **Driver problems (fixed on `fix/macwave-drivers`, `26713d8b`).** (a) A synthetic End (`key code 119`) leaves the fn flag set in the combined session state; the app then waits 3 s for "held modifiers" and shows a card (`modifier_wait_timed_out: true`). This also explains the earlier S-20 wave's cards. (b) With that stale flag, WebKit drops Unicode-string key events. (c) S-26a's grep was case-sensitive. (d) S-36 posted ⌘S/⌘A⌘C without checking the front app. (e) S-29a resume took full-screen screenshots.
7. **Drivers still hard-code `./handy`.** Since `c26c54d9` the `--no-bundle` binary is `target/debug/wispr-bro`; `wb-s05/app.sh`, the S-05/S-06/S-11/S-12a/S-19a/S-19b/S-20/S-36 take scripts and `wb-s09-soak.sh` look for `handy --start-hidden` and call `./handy --cancel`. A symlink does not work (Tauri's resource lookup panics with `UnknownPath`); this run used `cp -c wispr-bro handy`. A `./handy --cancel` also hung for 9 min once and had to be killed. Not fixed here (touches 15 drivers).
8. **S-27.2: Delete all relaunches with the original arguments.** `app.restart()` kept `--start-hidden`, so the relaunched app showed nothing; onboarding appeared on the next activation. Only matters for CLI/test launches; the login item has no arguments.
9. **S-22: the first-run "Your notifications live here" popup covers the View changes diff** when ⌥O opens the Hub for the first time.
10. **S-36: no editor evidence yet.** The read found 1 code name in 34 characters (the screen-reader text area around the caret), not `getUserById`, and a fresh Cursor profile puts a Log In window over the editor. Needs a prepared throwaway Cursor profile (signed out but past the welcome screen) or a person.
11. **S-38.3: parking forgets the Hub page.** The rebuilt main window loads `/` (home). Before parking, a hidden Hub reopened on its last page.
12. **S-07b (outside this wave): the speech-model policy loops under load.** With the machine at load ~60-96, the policy measured factor 18.2 and chose `parakeet-tdt_ctc-110m` over `parakeet-unified-en`; it downloaded 110m, then the running swap put unified-en back and deleted 110m, then the policy downloaded 110m again (`models: downloading a better speech model parakeet-tdt_ctc-110m` repeated at 01:51, 01:59, …, once also `could not select … Failed to load model`). Each cycle re-downloads 135-731 MB from Hugging Face. During one cycle a take's paste waited 17 s (route at 01:34:13, paste at 01:34:30, `to_paste_ms` 55): the insert path was blocked until the download finished.
13. **Portable marker.** An empty `Contents/MacOS/portable` is ignored unless `Data/` already exists; the first launch then writes to `~/Library/Application Support/<id>`. MAC-TEST-SCRIPT says "add `Contents/MacOS/portable`"; it should say to write `Handy Portable Mode` into it.
14. **Stuck fn flag from elsewhere.** At the start of the run the combined session flags already had `SecondaryFn` set (not from this run). One `fn up` cleared it.
