## Handy strengths to keep

1. **Non-activating overlay**: the NSPanel cannot become key and does not activate the app (`overlay.rs:27-34`, `:456-476`), so dictation never steals focus. R1 saw Wispr move focus on a bar click. Every new clickable state (bar, ✓, card) must keep this.
2. **Exactly-once, cancel-safe pipeline**: paste lock, cancel generations, session counter, and coordinator "remembered press" while busy (`clipboard.rs:18-20`; `actions.rs:81-83`, `:777-849`; `transcription_coordinator.rs:335-376`), with extensive unit tests.
3. **Receipt-based "reliable paste"** with concealed pasteboard types (`paste_tx/mod.rs`, `paste_tx/macos.rs`). This is better than a timer; it should become the default once validated.
4. **Secure Input awareness**: detects Secure Event Input, shadows keyed hotkeys through Carbon, explains it in the tray (`secure_input.rs:1-19`; `tray.rs:474-493`). An fn (modifier-only) default is naturally robust here.
5. **Honest capture readiness**: arming animation, and the start chime and mute only after the first real sample (`actions.rs:549-588`; `RecordingOverlay.tsx:32-35`).
6. **Live transcript panel** (Live style), which Wispr does not show.
7. **Mic robustness**: falls back to default on device loss and persists it (`managers/audio.rs:645-663`); clamshell mic; channel select; device cache.
8. **Layout-aware Cmd+V** (`input.rs:77-133`), alternative insertion methods, auto-submit, trailing space.
9. **Overlay placement**: follows the display under the cursor, sits above the Dock (work area), works on all Spaces and over full-screen apps (`overlay.rs:178-278`, `:471-475`).
10. **SMAppService login item** attributed to the app (`autostart.rs:1-9`); tray-icon recovery (`tray.rs:627-650`); start-hidden with correct activation policy (`lib.rs:129-163`).
11. **Cancel during processing** from the pill ✕ (`RecordingOverlay.tsx:278-286`).

## Rough edges found in code

1. **Silent no-op when no model is usable**: `TranscribeAction::start` returns after a `warn!` with no UI (`actions.rs:466-474`). In a product with auto-chosen models, a first-run press during download would look broken.
2. **Errors go to an invisible window**: recording, paste and transcription errors are main-window toasts (`App.tsx:155-207`), while the pill just hides (`actions.rs:838-848`, `:881-899`).
3. **Legacy clipboard restore loses data and can race**: text or image only (`clipboard.rs:81-90`, `:123-137`); fixed 60 ms delays (`settings.rs:664-670`); the documented race (`paste_tx/mod.rs:3-7`). The better path is debug-gated off (`settings.rs:514-518`).
4. **Transcripts leak to clipboard managers on the legacy path** (no concealed types, `clipboard.rs:50-61`).
5. **Esc is not available during transcription or post-processing** (`actions.rs:628-629`; `handler.rs:61-68`).
6. **Empty bindings are rejected** (`shortcut/mod.rs:169-172`), so Wispr's "not set" state cannot be represented.
7. **Silent backend fallback can drop an fn binding**: a handy-keys init failure persists the Tauri backend (`shortcut/mod.rs:44-55`) and Tauri resets fn bindings to defaults (`shortcut/mod.rs:486-547`; `tauri_impl.rs:52-58`).
8. **Tap-to-lock with fn is accident-prone**: the HoldOrToggle default (`settings.rs:184-185`) locks on any press under 300 ms; with fn as the key, fn+arrow or fn+F-key use would start hands-free dictation (inferred from `handy-keys/src/manager.rs:33-52`).
9. **Tray "Copy last transcript" is always enabled** and fails silently when empty (`tray.rs:518-524`, `:656-673`).
10. **Overlay geometry is duplicated by hand** between Rust and CSS (`overlay.rs:36-54`; `RecordingOverlay.css:21-34`). Each new state (label, card, three buttons) must update both.
11. **Mic levels exist only inside the overlay** (`overlay.rs:739-766`), so onboarding and settings cannot show a meter without new plumbing.
12. **Mute shells out to `osascript`** on every dictation (`managers/audio.rs:102-110`, `:200-216`).
13. **Tray exposes model choice and unloading** (`tray.rs:546-569`), against the "never pick a model" rule.
14. **Default history limit is 5 entries** (`settings.rs:676-678`). This is outside this area, but it limits copy/paste-last recovery and the soft-failure story.

## Platform concerns (macOS)

- **Accessibility permission** is already required (CGEventTap with blocking, enigo injection). AX focus queries (A-50, A-51) use the same permission, so there is no new prompt. Shortcut and enigo initialization is deferred until after permissions (`lib.rs:192-195`, `:221-224`).
- **Globe/fn key**: macOS binds 🌐 to the emoji picker, input-source switching or Apple Dictation (System Settings > Keyboard). Whether handy-keys blocking stops that is `unknown`. Onboarding may need to ask the user to set it to "Do Nothing".
- **Electron/Chromium AX**: focused-element detection is unreliable in Slack, VS Code, Discord and Chrome unless AX is enabled per app. A focus check must not block insertion when uncertain.
- **Secure Event Input**: keyed hotkeys need the Carbon shadow; fn-only does not (`secure_input.rs:4-7`). fn chords (fn+Space, fn+Ctrl) are "uncovered" under Secure Input (`secure_input.rs:39-40`).
- **Activation policy** (Dock toggle) transitions are fragile on macOS 26 (`lib.rs:129-146`).
- **Non-key panels and hover**: mouse-moved and hover events in a non-activating, non-key NSPanel need verification before committing to the A-01, A-02 and A-04 designs.
- **Bluetooth input** switches headsets to HFP (low-quality, music pauses). This motivates the built-in "recommended" default (A-38).
