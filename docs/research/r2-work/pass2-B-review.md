## Automatic model choice: verified facts

**Data per model in the catalog** (`node_modules/@handy-computer/models/catalog.json`, identical to `src-tauri/src/catalog/catalog.json` by `diff`; verified-in-code):
- Fields: `id`, `name`, `description`, `repository`, pinned `revision`, `license`, `family`, `parameters` (e.g. "618M"), `languages`, `capabilities` {streaming, translate, languageDetection, timestamps}, `quant` (default, Q8_0 for all curated), `role`, `curated`, `minEngine`, and `files` per quant (F32/BF16, F16, Q8_0, Q6_K, Q5_K_M, Q4_K_M) with byte size and sha256.
- `results[id]`: per-language FLEURS-test error with `ciLower`, and `performance.accelerated` / `performance.cpu` real-time factors.
- `benchmarks`: quant Q8_0; speed measured on **ryzen-4750u**, Vulkan (accelerated) and CPU.
- `methodology`: dictation 30 s, free wait 3 s, wait weight 0.5, overall max wait 5 s, max language error 20 %, note-min 15 %, experimental 30 %, fast-CPU max wait 4 s, accurate max wait 10 s.
- **Not in the catalog:** RAM or memory footprint, Apple Silicon or Metal benchmarks, benchmarks for non-Q8 quants. **Licences are present** (pass 1 omitted this): the default English and European picks are `cc-by-4.0` (attribution required); `nemotron-3.5`, `Fun-ASR-*` and `SenseVoiceSmall` are `other`. See B-204.
- Counts: 76 models, 29 curated ASR, plus `lang-id-voxlingua107-ecapa` (45.3 MB), `silero-vad-v6.2` and a diarizer. 51 languages are "recommendable" (`getPreferredRecommendationLanguages`).

**How picks are computed** (`recommendations.js:64-226`, `create.js:39`; verified-in-code):
1. Candidates must speak every chosen language and have both a measurement for each language and an accelerated RTF (`:70-77`).
2. Error = geometric mean over the languages. Score = error + 0.5 x max(0, accelWait − 3 s) (`:80-96`).
3. Pool: usable models (worst error < 20 %), preferring those that need no manual language choice (`:169-176`). A "manual" choice only arises with 2+ languages the detector cannot separate; Handy's detector usually covers them.
4. **Best** = lowest score among pool models whose accelerated wait is ≤ 5 s; **if none, lowest score in the whole pool, ignoring the budget** (`:177-180`). **Fast** = most accurate pool model with CPU wait ≤ 4 s (`:184-190`). **Accurate** = most accurate with accelerated wait ≤ 10 s (`:191-193`).
5. The picks are machine-independent by design (`:150-157`). Handy calls `catalog.recommend(languages)` without an engine version and **drops** (does not replace) picks the backend does not offer (`src/lib/models/catalog.ts:97-109`).

**8 GB Mac** (inferred unless marked):
- Apple Silicon 8 GB: the default files (731-936 MB at Q8_0) are about 10 % of RAM. Resident memory is roughly the file size plus activations (no footprint data in the catalog: verified absence). Memory risk is low. The real unknown is **speed**: all benchmarks come from a Ryzen 4750U iGPU. An M1's Metal GPU is plausibly as fast or faster, but this is unmeasured. Handy unloads idle models after 5 min (`settings.rs:150-160`, per E-82), so the first dictation after idle pays a reload (duration unknown).
- The "Accurate" role for en/European languages is Qwen3-ASR-1.7B at 2,185 MB and 7.3 s accelerated. Never pick it silently on 8 GB.
- **Intel Mac (any RAM):** CPU-only build. Use the **Fast** role. For en/European it is the same model (2.1-2.3 s CPU), so nothing changes. For ja/zh/ko it changes to Fun-ASR-Nano or SenseVoiceSmall. For the six whisper-large-v3 languages, CPU waits of about 31 s per 30 s are unusable; set expectations (B-208).
- Lower quants (Q4_K_M: parakeet-unified 477 MB instead of 731 MB) exist in the catalog, but Handy downloads only the default quant. The mirror hosts only default quants (`catalog/mod.rs:384-388`), and no accuracy numbers exist for them (verified-in-code). They are not a free option.

**Suggested silent policy** (inferred, for R4/R5): languages = OS seed (+en) → `recommend()` → if Intel/no GPU or RAM < 8 GB, take `fast`; if free disk at the HF cache is under 2 x download + 1 GB, take the smallest usable pick or stop with a clear message; if the best wait is over 5 s on the machine's tier, take `fast` and say the language is slow; after the first timed take, switch to `fast` silently if `isTooSlow`.

## Open questions resolved

1. **Does the download survive closing the window?** Yes, while the app keeps running. CloseRequested is prevented and the window is hidden (`src-tauri/src/lib.rs:1103-1106`), so the webview and the backend download continue. **Quitting** stops it. Partials are kept (HF `.sync.part` in the cache, `model.rs:2097-2104`; mirror/URL `.partial`, `model.rs:2336-2341`). On relaunch, onboarding marks the download failed and waits for Retry (`OnboardingFlow.tsx:58-67`), which resumes. verified-in-code
2. **Can handy-keys bind fn alone?** At the library level, yes. The macOS tap tracks keycode 0x3F and emits an FN-only key event (`handy-keys-0.3.4/src/platform/macos/listener.rs:320-340`). Modifier-only hotkeys are supported (`manager.rs:429-445` test). Handy's HandyKeys validator accepts fn (`shortcut/handy_keys.rs:411-419`), and HandyKeys is the macOS default (`settings.rs:238-245`). Remaining risks (from A-35, not resolved here): the Globe key's system action may still fire; Handy silently falls back to the Tauri backend, which rejects fn (`tauri_impl.rs:52-58`); a `Dictation` keycode quirk is documented (`handy-keys-0.3.4/src/types/key.rs:173-185`). The event tap needs **Accessibility**, not Input Monitoring (`listener.rs:72`, `permissions.rs:5-10`). verified-in-code
3. **Backend retry policy.** Hugging Face first: up to **4 attempts** (4 parallel streams, then 1, 1, 1), backoff 2 s, 4 s, 8 s, each attempt resuming the partial. A **60 s no-progress watchdog** cancels a wedged attempt; a single-stream stall goes straight to fallback. Then mirrors (`https://blob.handy.computer`, `catalog/mod.rs:36`) with HTTP Range resume, 15 s connect timeout, sha256 against the compiled catalog, and safe handling of 200/206/416. After all of that fails: error event + toast, and no automatic retry later. verified-in-code (`model.rs:2008-2160`; `download.rs:20-27`, `:217-311`)
4. **When is the 45 MB detector downloaded?** Whenever the chosen model is multilingual and cannot detect language itself, regardless of how many languages the user speaks (`policy.rs:106-110`; `model.rs:1915-1932`). If the detector fails, the model download continues anyway (`model.rs:1880-1887`). verified-in-code
5. **Where do models go?** HF path: the shared Hugging Face cache (`Cache::from_env()`); portable builds set `HF_HOME` into the app data dir (`portable.rs:44-45`). Mirror and URL path: the models dir. verified-in-code; default `~/.cache/huggingface/hub` location inferred from hf-hub conventions.
