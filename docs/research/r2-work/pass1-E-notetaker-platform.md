## Headline findings

1. **System audio capture is closer than it looks.** Handy's mic crate `handy-recorder` enumerates input devices only (`~cargo/handy-recorder-0.1.0/src/backend/cpal/mod.rs:131-139,212`), but the cpal fork underneath it (`handy-cpal 0.18.2`) already implements **macOS Core Audio process-tap loopback**: opening an input stream on an *output* device creates a global `CATapDescription` tap plus a private aggregate device (`~cargo/handy-cpal-0.18.2/src/host/coreaudio/macos/device.rs:727-736`, `loopback.rs:96-109`). Requires macOS 14.6+ per its README (`README.md:60`). WASAPI loopback exists for Windows too (`src/host/wasapi/mod.rs:24`). `verified`
2. **Diarization model and runtime already exist upstream of Handy.** `transcribe-cpp 0.4.0` exposes `DiarizeSession` returning `SpeakerSegment`s (`~cargo/transcribe-cpp-0.4.0/src/diarize.rs:1,53,117`), and Handy's bundled catalog lists a Sortformer 4-speaker streaming diarizer (`src-tauri/src/catalog/catalog.json:1525-1540`, Q8_0 ~139 MB) that Handy deliberately filters out (`src-tauri/src/catalog/mod.rs:316-320`). `verified`
3. **Long-form transcription is solid**: live streaming for streaming models, VAD-cut live chunking otherwise (`managers/transcription/policy.rs:51-59`, `live.rs:1-2`, `chunked.rs:1-2`), background file jobs that yield to dictation (`managers/transcription_jobs.rs:1-2`), and file import into History (`commands/history.rs:85`, `transcribeFiles.ts:26`). `verified`
4. **No local LLM runtime.** Summary, "Ask anything" and "What did I miss?" need one. Handy only has cloud providers (default `openai`), Apple Intelligence (macOS 26+, Apple Silicon) and a "Custom" OpenAI-compatible endpoint defaulting to `http://localhost:11434/v1` (`settings.rs:710-812`). `verified`
5. **Release pipeline is reusable but hard-wired to the upstream author**: updater pubkey and endpoint (`tauri.conf.json:84-90`), Windows Azure signing command (`tauri.conf.json:77`), identifier `com.pais.handy` (`tauri.conf.json:5`). The macOS sign + notarize + `latest.json` path through `tauri-action` only needs our secrets (`build.yml:221-243,449-479`). `verified`
6. **Defaults that clash with a Wispr-like product**: history keeps **5** entries by default (`settings.rs:676-678`), file log level **Debug** (`settings.rs:656-658`), update checks on (`settings.rs:596-598`), with the update check silently swallowing errors (`UpdateChecker.tsx:108-109`). `verified`

## Release and update: exact steps to ship our own signed, notarized, auto-updating macOS build

Grounded in `release.yml` and `build.yml`. Nothing here was executed.

1. **Generate our updater key pair** (`bun run tauri signer generate -w ~/.tauri/<app>.key`). Store the private key and password as repo secrets `TAURI_SIGNING_PRIVATE_KEY`, `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` (consumed at `build.yml:463-464`).
2. **Edit `src-tauri/tauri.conf.json`** (keep as a small fork-only diff): `productName` (`:3`), `identifier` (`:5`, e.g. reverse-DNS of our domain; changing it later orphans user data and permissions), `plugins.updater.pubkey` (`:86`) = our public key, `plugins.updater.endpoints` (`:88`) = `https://github.com/<our-org>/<repo>/releases/latest/download/latest.json` (or our static host). Remove or replace `bundle.windows.signCommand` (`:77`) so Windows jobs don't try upstream's Azure account. Optionally raise `minimumSystemVersion` (`:42`).
3. **Apple secrets** (Developer ID Application certificate exported as base64 p12): `APPLE_CERTIFICATE`, `APPLE_CERTIFICATE_PASSWORD`, `KEYCHAIN_PASSWORD` (`build.yml:224-226`), and notarization: `APPLE_ID`, `APPLE_PASSWORD` (app-specific password; `APPLE_ID_PASSWORD` is also passed), `APPLE_TEAM_ID` (`build.yml:453-456`). The identity is auto-detected by grepping "Developer ID Application" (`build.yml:240-242`).
4. **Trim the release matrix** in `release.yml:47-69` to the two macOS entries (`macos-26` arm64, kept for the Apple Intelligence SDK, and `macos-latest` x86_64) until Windows/Linux are in scope. Consider `asset-prefix` (`release.yml:77`) to our name.
5. **Bump version** in `tauri.conf.json:4` (the workflow reads it there, `release.yml:17-23`) and `Cargo.toml:3` (kept in sync by convention; also read by `flake.nix:29-31`).
6. **Run "Release"** (`workflow_dispatch`, `release.yml:3`). It creates a draft release `v<version>` with generated notes (`release.yml:25-38`), then `tauri-action` builds, signs, notarizes, and uploads `.dmg`, `.app.tar.gz`, `.sig` and `latest.json` (`build.yml:449-479`; upload behavior `inferred` from tauri-action).
7. **Publish the draft.** `releases/latest/download/latest.json` only resolves to a published, non-prerelease release (`inferred`). Then verify: `spctl -a -vv` and `xcrun stapler validate` on the .app; install the previous version and check the footer Update flow (`UpdateChecker.tsx:122-162`).
8. **Optional hardening**: make the update check periodic (E-53), surface errors, and move `main-build.yml`'s trigger (`:8-9`) to our branch name if we want CI on every push.
9. **Store distribution notes** (`inferred`): Homebrew cask can point at the GitHub dmg; the in-app updater should then be disabled for cask installs or left to coexist (cask `auto_updates true`). The `HANDY_DISABLE_UPDATER` env path (`settings.rs:1376-1381`) exists for package-manager builds.

## Handy strengths to keep

- Process-isolated inference with crash/hang recovery and GPU-to-CPU fallback (`engine_supervisor/mod.rs:1-20`).
- Streaming + VAD-chunked long-form decoding with a single policy point (`managers/transcription/policy.rs:49-69`).
- Background job queue that yields to dictation and survives worker crashes (`transcription_jobs.rs:1-2,253,339`).
- File import (picker + drag-drop) with wide codec support (`transcribeFiles.ts`, `FileDropOverlay.tsx`, `Cargo.toml:59-61`).
- Pinned-revision, hashed model downloads with resumable mirror fallback and stall watchdog (`catalog/mod.rs:84-86`, `model.rs:2030-2075`).
- Careful settings salvage/migration and forward-compatible DB columns (`settings.rs:1112-1135`, `history.rs:38-40,163-185`).
- Complete CI signing/notarization/updater pipeline and 26-locale i18n with a CI parity check.
- Upstream engine crates already include what Notetaker needs at the lowest level: loopback capture in `handy-cpal`, diarization in `transcribe-cpp`.

## Rough edges found in code

- Default `history_limit = 5` (`settings.rs:676-678`): too small for a Wispr-like history.
- Default file log level Debug (`settings.rs:656-658`).
- Update check runs once on window mount, errors only in console (`UpdateChecker.tsx:50-77,108-109`).
- Models land in the global HF cache outside app data in non-portable mode (`model.rs:316-320`), complicating "delete my data".
- Recording kept fully in RAM until stop (`sink.rs:70-79`); fine for dictation, not for meetings.
- Upstream identity hard-coded in Windows signing (`tauri.conf.json:77`) and LLM request headers (`llm_client.rs:187-195`).
- CSP disabled (`tauri.conf.json:16`).
- Default post-processing provider is a cloud service (`settings.rs:710-712`), even though disabled by default.
