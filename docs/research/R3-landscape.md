# R3: Competitive landscape (merged and verified)

## 1. Purpose and how to read

This file merges three research passes into one deliverable: `r3-work/R3a-web-stack-peers.md` (Handy forks and web-stack apps), `r3-work/R3b-native-mac-peers.md` (native macOS apps) and `r3-work/R3c-commercial.md` (Wispr Flow documentation and commercial rivals). An independent verifier re-checked licenses, health numbers, more than 40 code claims and 17 documentation pages, and fixed what was wrong. The log of every check is in `r3-work/R3-verification-log.md`. Go to the working files for longer reasoning and full per-project matrices.

It answers three questions for the build: what open-source code we can reuse (and under which license), what Wispr Flow does where R1 had unknowns, and where a free local product can beat paid apps. It does not decide scope; R5 does.

**Tags.** (obs) = read in code, LICENSE, docs or issue. (inf) = inferred from what was read. (unk) = not determined. **[verified]** = re-checked by the verifier on 2026-10-28 (code opened in the clone, LICENSE read, HF API queried or doc page re-fetched). Claims without [verified] come from one pass only and are marked (obs) by that pass.

**License status of an idea.** *Code* = permissive (MIT/Apache-2.0/BSD), file not GPL-derived: may be ported with attribution. *Port* = permissive but written in Swift/JS, so the code is a reference to rewrite in Rust. *Idea only* = GPL/AGPL, GPL-derived file, or docs-only reading: reuse the design, never the code.

**IDs.** AF-xx, DEC-xx, RC-xx and row ids (A-xx…E-xx) refer to `R2-gap-analysis.md`. W-, S-, SP- and other keys point to the source table in R3c §1; URLs are given inline here where a fact matters.

**Name clash.** Two different projects are called OpenFlow. **OpenFlow-T** = `avijeett007/openflow` (Tauri Handy fork, R3a). **open-flow** = `Robj1925/open-flow` (Swift, R3b). The working files call both "OpenFlow".

## 2. Executive summary

### 2.1 The 10 most useful findings for our build

1. **The local LLM cleanup chain already exists in MIT Rust on a Handy base.** SpeakoFlow runs `llama-server` as a child process on its own loopback port (11436, 4,096-token context), pins temperature to 0, asks for a `{cleaned_text}` JSON schema, prewarms the model while the user is still speaking, and rejects bad output: empty, punctuation-only, a leaked channel name, a prompt echo, or more than max(80, 3×input) characters. Any rejection keeps the raw text. [verified] This is AF-01 + AF-02 nearly as R2 designed them. Port the parts; `local_llm.rs` alone is 2,917 lines. → D-67, D-212, D-11, D-12, DEC-03.
2. **Three Apache-2.0 cleanup models trained for dictation exist** [verified on HF]: SpeakoFlow Mini (Qwen3.5-0.8B, 833 MB Q8_0), Muesli v12 (Qwen3.5-0.8B 529 MB and 2B 1.27 GB, Q4_K_M GGUF), VoiceInk-Refine-Mini (Qwen3.5-0.8B, published 2026-10-28). R3a's "SpeakoFlow Mini is the only one" was wrong. SpeakoFlow Mini's own card reports 92.6 % restraint, 48.8 % edit accuracy, **10.7 % content damage**, English only [verified]. No default without our own eval and output validators. → DEC-03, DEC-13, B-204, D-67.
3. **An always-visible, clickable, non-activating pill in our exact stack.** Tolkovo (MIT, Tauri 2 + tauri-nspanel) builds a second panel with `hides_on_deactivate(false)`, `accept_first_mouse(true)`, `focusable(false)` and `PanelLevel::Status`. It also sends the private `_setPreventsActivation:` after creation, re-shows the panel on every Space change, and handles click-to-toggle plus a manual drag [verified]. Wispr's docs give the product rules: the bar stays hidden until setup ends, follows the cursor's display, keeps the target field selected when clicked, and offers "Hide for 1 hour" [verified]. → A-01, A-04, A-17, A-66, A-212, AF-09, RC-01, DEC-25.
4. **Hotkeys need self-healing, and Wispr's tap grammar is now documented.** Hex legacy (MIT) re-enables a disabled tap from a 100 ms `tapIsEnabled` watchdog and rebuilds it on wake and session change [verified]; open-flow does the same with a 5 s timer [verified]. SpeakoFlow still has Handy's silent hook death (only an `error!` log, then the thread returns) [verified], so no Handy fork has fixed A-208. Wispr's rules [verified]: a press released under 0.5 s never pastes; a double press within 0.5 s locks hands-free; a third quick press cancels; a stop within 0.5 s of start cancels. → AF-08, A-208, A-22, A-23, A-34, DEC-09.
5. **Globe/fn: one permissive project ships suppression, and its comment explains why a tap cannot do it.** OpenWhispr's MIT Swift helper sets `AppleFnUsageType` to "Do Nothing" through the private `TISUpdateFnUsageType` (via `dlsym`). It writes a marker so a crashed run restores the user's original value, and does this automatically whenever the user binds a Globe hotkey (no consent step) [verified]. Its source comment says macOS runs the Globe action from WindowServer before any event tap (inf: answers RC-02's direction; still test it). It also emits `FN_INTERRUPTED` when another key is pressed with fn [verified]. R3b's "no permissive project suppresses Globe" was wrong. → RC-02, A-35, A-201, DEC-09.
6. **A ready Rust Accessibility layer.** SpeakoFlow's `smart_spacing/macos.rs` (MIT, `objc2-application-services`) runs every AX call on one thread with a 0.2 s timeout. It turns `AXManualAccessibility` on for Chromium/Electron apps and off again 60 s after the last read, never writes `AXEnhancedUserInterface`, and skips secure fields, Secure Input and terminals [verified]. That is the missing AF-05 layer. Add OpenWhispr's editable-target rule [verified] and TypeWhisper's fail-open rule (idea) for the "Select a textbox first" card. → AF-05, A-50, A-51, A-15, D-58, RC-04.
7. **Insertion and clipboard: Rust code plus Wispr's exact policy.** hex (Rust, MIT) snapshots every pasteboard item and flavor, marks its own write with `org.nspasteboard.TransientType`/`AutoGeneratedType`, and restores only if nothing changed. It also detects Chromium 155/156, which drops ⌘V, and types instead [verified]. Wispr's policy [verified]: on Mac the restore waits up to ~7 s in busy apps such as Chrome; file contents, PDF, RTFD and audio are not restored; the recovery card's Copy replaces the clipboard and does not restore it. → AF-17, A-47, A-48, A-53, A-15.
8. **First run: nobody is fully silent, but every piece exists.** hex (MIT) publishes a per-language recommendation table measured on the **same `handy-computer/transcribe.cpp` Q8_0 GGUFs Handy uses**, with one model per language enforced by a test [verified]. SpeakoFlow refuses the hotkey while the model downloads and shows progress on the pill (`speech_readiness.rs`) [verified]. OpenSuperWhisper bundles `ggml-tiny.en.bin` (77 MB) as a bootstrap [verified]. MacParakeet (GPL, idea only) picks Parakeet silently unless the system prefers ko/ja/zh/yue. → B-50, B-202, B-47, B-49, AF-03, AF-20, DEC-01, DEC-02.
9. **Per-app styles without the cloud.** OpenWhispr (MIT) has about 80 app, browser and site signatures. A browser is judged by its page host via AX when exposed, else by the site name at the end of the window title, and the tone suffix says "Restyle only; do not add or remove information" [verified]. Muesli (MIT) reads the browser URL through AX `kAXDocumentAttribute` with no Automation prompt [verified]. → D-18–D-24, DEC-23.
10. **Distribution: sign with a stable Developer ID from day one, and update only when idle.** OpenFlow-T's README says each ad-hoc-signed auto-update may make macOS ask again for Accessibility, Input Monitoring and Microphone [verified]. VoiceInk #829 reports the same TCC reset (obs). Wispr's updater [verified]: on by default, waits ≥20 min after the last dictation, never installs during dictation or recording, relaunches quietly to the bar, pauses 24 h after 3 failures. Talkify defers Sparkle while dictating [verified]. → AF-11, DEC-16, DEC-17, E-51–E-54, E-215.

### 2.2 Differentiators a free local product can own

1. **Local AI cleanup at $0.** Wispr transcribes in the cloud, always [verified W25]. Superwhisper's only local LLM (S1-mini, 462 MB) is English-only, Message/Mail modes only, and Pro; its default LLM is the cloud S1-Language [verified]. Aqua, Willow and Monologue format in the cloud (R3c, obs). Note: our cleanup models are English-first too (finding 2), so "every language" needs a multilingual model and an eval before we claim it.
2. **No account, nothing lost on sign-out.** Wispr requires a browser sign-in, and signing out deletes local transcript history (W13, W30, obs).
3. **Zero network by default, verifiable.** Even with Context Awareness off, Wispr sends the app name and website domain with each dictation [verified W10]. Its usage statistics are collected "regardless of your data controls" [verified W25]. Spokenly sends anonymous analytics unless Local Only Mode is turned on, and its doc does not say that mode is the default [verified]. Ship the local-only behavior as the default, with a published network inventory (AF-12).
4. **Silent model choice.** Every commercial local app shows a model library (Superwhisper, MacWhisper, Spokenly, VoiceInk). Among open source, only MacParakeet (GPL) chooses silently. Doing it in permissive code is open ground. → DEC-02.
5. **No caps.** Wispr Free has 2,000 words/week on desktop [verified W26] and a 20-minute session cap [verified W1]; Aqua and Monologue have 1,000 words (obs). Use a silence auto-stop instead (Apple stops after 30 s of silence, obs).
6. **Paid-only features free:** Command Mode and voice "Press Enter" are paid and off by default at Wispr (W4, W1, obs). Superwhisper puts Parakeet behind Pro (S6, obs). Spokenly puts the notch/capsule styles in its $29 tier (SP1, obs).
7. **Local context with a visible receipt.** Read AX text on the Mac only, and show in History what context was used (Superwhisper shows the prompt, S11, obs).
8. **No telemetry, really.** Muesli (TelemetryDeck in release builds), FluidVoice (weekly ping that cannot be disabled) and MacParakeet (opt-out telemetry plus a feed request at each launch) all phone home (§7).

### 2.3 Main traps (detail in §7)

- **GPL inside a permissive repo.** BetterWispr (Apache-2.0) contains code adapted from VoiceInk (GPL-3.0) in **11 files**, including `App/AppModel.swift`. R3b listed 9 and missed `AppModel.swift` and `WarmUpClip.swift` [verified].
- **Cloud and telemetry defaults** in otherwise-MIT apps (OpenWhispr cloud defaults, Muesli TelemetryDeck and ChatGPT summaries).
- **Private APIs** (`TISUpdateFnUsageType`, `_setPreventsActivation:`) work today and may break on an OS update.
- **Ad-hoc signing** breaks permissions on every update.
- **Small models damage meaning** (10.7 % content damage on the best-documented one).

## 8. Open questions

1. **RC-02:** does macOS run the Globe action even when our tap blocks the fn press? OpenWhispr's comment says it does, because WindowServer runs it before any tap. Test on macOS 14, 15 and 26, then decide between consented `TISUpdateFnUsageType` and onboarding copy.
2. **Cleanup model:** which of SpeakoFlow Mini / Muesli 0.8B / Muesli 2B / Refine Mini wins on our own eval (content damage, restraint, latency on an 8 GB M1, non-English)? Is any of them multilingual enough to back "free local cleanup in every language"? (RC-11, DEC-03)
3. **Pill:** does Tolkovo's nspanel recipe deliver first-click and hover in Handy's overlay webview without private-API side effects on macOS 26? Does an idle webview grow in memory over hours (RC-10)?
4. **Bootstrap vs queue (DEC-01):** a bundled tiny model (~77 MB, English-only) vs SpeakoFlow's "refuse and show progress" vs recording into a queue.
5. **SpeakoFlow porting cost:** how much of `local_llm.rs` and `actions.rs` depends on its many providers and settings? (inf: substantial; port the parts.)
6. **Chromium 155/156:** is the ⌘V race still relevant once Chrome 157 is widespread? (VoiceInk #1000 says it was fixed in 157.)
7. **Process tap permission:** MacParakeet #924 reports the tap works with only System Audio Recording permission; confirm for our signing and entitlements (RC-08).
