# Wispr Bro: start here

Wispr Bro is a free, fully local, open-source (GPL-3.0) macOS dictation app. Hold fn, speak, release, and clean text lands in whatever field has focus. It matches Wispr Flow's consumer experience, but everything runs on the Mac: no account, no cloud, no telemetry, no usage caps, auto-updating, and the user never picks a model. Apple Silicon first; Intel, Windows and Linux later.

This repo is a fork of [Handy](https://github.com/cjpais/Handy) (MIT; Tauri 2 + Rust + React 18/TypeScript). Branch `wispr-bro` is ours; `main` tracks the `upstream` remote.

1. **This file.**
2. **`docs/research/R5-prd-and-slices.md`**: the plan. Product rules (§1), scope (§2), decisions (§3), fork architecture (§4), performance budgets (§5), slices F-xx, RS-xx, S-xx, N-xx (§6-§10), exit criteria (§9). It is the source of truth for what to build next.
3. When a slice needs detail, follow its ids into:
   - `docs/research/R1-wispr-flow-teardown.md`: how Wispr Flow looks and behaves (the target experience).
   - `docs/research/R2-gap-analysis.md`: every feature compared with Handy's code (row ids A-xx..E-xx, architecture findings AF-xx, decisions DEC-xx, runtime checks RC-xx).
   - `docs/research/R3-landscape.md`: how other apps solved the same problems, plus Wispr Flow's documented behavior.
   - `docs/research/R4-parts-bin.md` and `docs/research/R4-addendum-gpl.md`: the exact open-source part to use for each capability, licenses, things we write ourselves (W-xx), runtime checks (RT-xx), ship checklist.
4. `AGENTS.md`: Handy's own developer notes (build commands, structure, conventions). Still valid for the upstream code.

Working files behind each deliverable are in `docs/research/r2-work/`, `r3-work/`, `r4-work/` and `r5-review.md`. Read them only when a deliverable points there.

## How to work

- **One slice at a time.** Pick the next slice in R5 whose dependencies are done. Build only that slice, to production quality (tests, translations, accessibility labels, dark mode). Order: M0 foundations (F-01..F-10), M0.5 real-Mac spikes (RS-01..RS-14, can run in parallel), then M1 slices S-01 onward. Do not start M2 (Notetaker, N-xx) until every M1 exit criterion in R5 §9 passes.
- **Reuse before writing.** For every capability, use the part R4 or the GPL addendum names (adopt a crate, vendor files, or port code with its license notice). Write our own code only for the W-xx items.
- **Thin layer on Handy.** Our code lives in the fork namespace (R5 §4.1). Upstream files get only the one-line hooks listed in R5 §4.2. Never add to Handy's `MIGRATIONS`, `AppSettings`, `collect_commands!` or `translation.json` files; fork strings go in the `fork` i18n namespace.
- **Licensing.** The app is GPL-3.0. New files carry `SPDX-License-Identifier: GPL-3.0-or-later`; ported files keep their original copyright line plus a modification notice; AGPL ports are marked `AGPL-3.0-only` and listed in NOTICE. Never copy Wispr Flow's code, prompts, UI text, sounds, icons or images; follow its behavior and structure only.
- **Privacy is a hard rule.** The app may contact only GitHub releases (updates) and Hugging Face (models). No other host, no telemetry SDK, no AppleScript. CI guards enforce this (R5 §4.12).
- **Verify, don't assume.** Run the tests and the slice's real-Mac acceptance checks. Never report a slice done without running them; say plainly what was not verified.
- **Commits.** Conventional commit prefixes; one slice per branch or PR.

## Execution protocol (owner-approved 2026-10-31; applies to every agent, Claude Code or Kimi)

Verification is batched by risk, not by slice. None of this weakens R5's exit criteria or the "verify, don't assume" rule above — the same checks run, on a better schedule.

- **Backend slices** (event tap, AX, clipboard, models, LLM, transforms, updates, erase, context awareness, vibe coding): real-Mac acceptance runs stay mandatory, but run **batched per wave** — one scripted run covers the wave's slices that share a harness (e.g. S-21/22/23 one transform run; S-19b + S-36 one browser/AX run). No more per-slice solo release-build Mac runs.
- **UI slices** (settings modal, menus, onboarding, tutorials, first-use chooser): the per-slice gate is the full Playwright suite (every state, light/dark, RTL, reduced motion, keyboard-only, axe) plus unit tests. Real-Mac evidence comes from **one consolidated Mac run per wave** (one scripted pass through the new screens), not one run per slice. VoiceOver-by-ear stays with S-37's checklist as planned.
- **Debug builds for GUI verification** using the slice test identities (`com.wisprbro.<slice>check` runs the product runtime). Release bundles only for CSP-sensitive checks and wave/RC runs.
- **Two lanes.** Builders work in worktrees in parallel and never wait on `~/wb-bench/gui.lock`; real-Mac runs are a single serialized verification queue driven by the orchestrator, overlapped with building.
- **No re-testing settled evidence.** A slice's acceptance = its own R5 checks plus its "Not verified" items. Cite, don't re-run: RS-xx spike results and earlier slices' soak numbers. CI guards + `cargo test` + lint + Playwright on every merge are the regression net.
- **Reuse the harness inventory** (`scripts/wb-s01`..`wb-s25`: take drivers, AX drivers, TTS takes, gui.lock, seeders, the local HF stand-in). New driver code only for genuinely new mechanics.
- **Batch the mechanical work.** 26-locale translations run per merge wave (machine flags allowed until S-37 as planned); bindings regeneration rides the merge commit (`WB_WRITE_FORK_BINDINGS=1 cargo test fork_bindings_are_current`). After merging slices that add frontend dependencies, run `bun install` before any Playwright run (a missing package puts Vite's error overlay on every spec). Format checks use `wb:format:check`, not upstream `format:check` (which lacks the fork ignores).
- **S-35 (Wispr Flow / Handy vocabulary importer) is deferred to 1.1**, which R5 risk #15 allows without failing §9.
- **Model routing (Kimi).** The orchestrator runs the strongest model; subagents are dispatched per task weight — hard slices and deep debugging to the top model, mechanical work (doc folding, translations, bindings regen, small fixes, test reruns) to the cheap pool entry. Claude sessions apply the same idea with their own tiering.
- **Shared compile cache.** `src-tauri/.cargo/config.toml` routes rustc through `scripts/wb-rustc-wrapper.sh`, which uses `sccache` when installed (`brew install sccache`; 60 GB cache) and plain rustc otherwise. Every worktree therefore reuses compiled dependencies instead of rebuilding ~10 GB each. Do not set a shared `CARGO_TARGET_DIR` across parallel worktrees (lock contention); sccache is the sharing layer.
- **Parallel builders: up to 6-7 with the shared cache.** Before sccache, more than 4 pushed load past 100 and stalled process launches (fseventsd/syspolicyd). Check `uptime` before starting another; hold new launches while the 5-minute load is above ~60.
- **Agent brief.** Builder agents get `docs/fork/AGENT-BRIEF.md` with its placeholders filled; keep it in step with this protocol.
- **Run independent work in its own worktree.** Long runs (release builds, Mac waves) use a dedicated worktree so merges into the main checkout never wait on them.
- **Clean up on merge, every time.** After a slice merges: remove its worktree and branch (`git worktree remove -f -f`, `git branch -D`), stop every server/app it started (dev servers, `llama-server`, test apps), and delete its test bundle and `~/Library/{WebKit,Caches}/com.wisprbro.<slice>check`. Worktree targets are 10-14 GB each.
- **Pre-recorded audio first.** Real-Mac takes use WAVs (make once with `say -o`, feed through file/injection paths); play through the speakers only when a check truly needs the live mic, once, at moderate volume. The owner works at this Mac.
- **Flaky tests get fixed, not re-run.** A test that fails under load and passes alone is a bug in the test (missing wait, too-tight timeout, shared state): fix it in the same wave.
- **Translation merges.** `bun run wb:check:translations` now also fails on duplicate keys in `fork.json`/`fork.flags.json` (a bad merge can duplicate a block and silently drop keys). On a locale conflict, rebuild the file from the base branch plus your slice's keys rather than hand-merging.
